# Releasing

`@contexture/mcp` is public from v1.0.0. Its documented exports and
`contexture` CLI follow Semantic Versioning: breaking public API changes require
a new major version.

## Public release checklist

1. Start from current `master` with a clean worktree. Complete the release
   scope, add a dated changelog section, and update the English documentation
   and its Simplified Chinese translation.
2. Set `package.json`, `package-lock.json`, and `PACKAGE_VERSION` to the exact
   release version. Keep `private` set to `false` and npm public access in
   `publishConfig`.
3. Confirm `conformance/specification.json` honestly reports the achieved
   `conformant` status; the release guard rejects every other status. Do not
   alter fixtures or golden bytes just to release.
4. Run `node scripts/verify-release.mjs v<version>`, then `npm ci` and
   `npm run check`. Inspect `npm pack --dry-run` and confirm the tarball contains
   `LICENSE`, both READMEs, declarations, CLI, templates, and every documented
   public subpath, with no credentials or stale build output. The check installs
   that tarball into an independent consumer and exercises a generated project.
5. Record current real-Host verification from the exact packed release
   artifact. Historical candidate runs do not satisfy the v1.0.0 Host gate.
6. Bootstrap v1.0.0 only after a maintainer confirms external ownership of the
   `@contexture` npm scope. The registry's current 404/uncreated result is not
   ownership proof. From a maintainer terminal, check out the audited v1.0.0
   commit, verify it, create its local tag, and publish that exact source in
   this order:

   ```bash
   git switch --detach <audited-v1.0.0-commit>
   npm ci
   npm run check
   test "$(node -p \"require('./package.json').version\")" = '1.0.0'
   git tag -a v1.0.0 -m 'Contexture TypeScript v1.0.0'
   node scripts/verify-release.mjs v1.0.0
   npm publish --access public --provenance=false
   ```

   Authenticate with interactive npm 2FA, or use an explicitly approved
   short-lived-token path outside repository automation. Never put credentials
   in this repository, workflow configuration, or command output. The initial
   interactive upload intentionally has no provenance attestation because npm
   provenance is generated by CI OIDC; configure npm Trusted Publishing after
   the package exists. Only after a successful upload, push the audited commit
   and its already-created `v1.0.0` tag together, so the source, tag, and
   package version remain exact. The `v1.0.0` tag workflow verifies the release
   but intentionally does not upload its already-published version.

7. For releases after v1.0.0, commit, create the exact matching tag
   (`v<version>`), and push it. The workflow publishes through Trusted
   Publishing:
   - GitHub user: `CarterShi01`
   - repository: `contexture-mcp-typescript`
   - workflow: `publish-npm.yml`
   - environment: `npm`
   - allowed action: `npm publish`

The workflow requires Node 24 and npm 11.19.1, validates tag/version equality
and fully conformant status, and runs the complete check. After the v1.0.0
bootstrap it publishes through OIDC with provenance and without a long-lived
token. Protect the GitHub `npm` environment with a required reviewer.

Never reuse or move a published version tag.
